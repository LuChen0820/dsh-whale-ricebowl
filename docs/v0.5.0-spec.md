# v0.5.0 设计草案：装饭喂鱼（对话级米饭库存）

> 状态：**已实现（v0.5.0）**。本文件保留为设计记录；用户文档见 README / README-En。

## 1. 为什么要改

0.4.x 的玩法是「每轮先押一碗，再按本轮实际用量吃、结算时比较预测 vs 实际」。
用户确认这不是想要的：**不是预测/押注，而是先给大肥鱼装饭，对话过程中每轮消耗 token（= 吃米饭），饭吃完就自动讨饭**。
所以 v0.5.0 换玩法，不是换措辞。

## 2. 核心规则

| 项 | 规则 |
| --- | --- |
| 单位 | 1 碗 = **1,000,000 token**（`config.tokensPerBowl`，可调） |
| 库存 | 每个对话（`sessionId`）独立：`allocated`（已装饭）/ `consumed`（已吃）/ `remaining = allocated - consumed` |
| 多碗 | 最多显示 **5 碗**（`maxBowls=5`，即 500 万）；装满 5 碗后继续加 token，**UI 不变**，数字标签显示真实剩余 |
| 装饭 | 菜单：装 1 碗（100 万）/ 2 碗（200 万）/ 5 碗（500 万）；对话中可随时添饭 |
| 消耗 | 回合结束时按本轮 `actualTokens` 扣饭：米饭减少 + 气泡报告「本轮吃了 X · 剩 Y（Z%）」 |
| 讨饭 | `remaining <= 0` 时**自动**进入讨饭状态（不管是否在跑） |
| 术语 | 装饭 / 添饭 / 吃了 / 剩饭 / 吃完了 / 讨饭；**不再出现** 预测 / 押注 / 结算 / 超了 / 省下 |

## 3. 状态与持久化

- `localStorage['dshwr-tank:v1'] = { v:1, order:[sid...], sessions:{ [sid]: { allocated, consumed, fedAt, updatedAt, turns } } }`
- 保留最近 30 个对话；切换对话时切换到对应库存；新对话 = 空库存（触发讨饭）
- 清理 0.4.x 旧键：`dshwr-active`、`dshwr-pending`（旧预测机制残留）
- 饭账历史（可选增强）：`dshwr-ledger:v1` 记录每轮 `{turn, consumed, remaining, at}`，供设置面板 + 最近对话列表

## 4. UI

- 碗区：**主碗**显示当前碗剩余比例；旁边最多 5 个**碗位**表示总库存（满碗 / 当前半碗 / 空碗）
- 标签：`剩 99.4 万（99.4%）` / 空时 `没有饭了`
- 每轮报告气泡：`这轮吃了 6,100 · 剩 99.4 万`
- 设置面板：现有开关 + **饭账**（本对话已装 / 已吃 / 剩余 + 最近会话列表）+ 清空
- 讨饭：立绘上下浮 / 歪头 / 朝碗前倾 + 张嘴「啊——」+ 气泡**间隔出现/消失**（约 4s 一次、显示 2.8s），文案随机且**不连续两次相同**
- 菜单不遮挡宿主余额气泡（沿用 0.4.x 约束）

## 5. 动画一致性（治本）

0.4.x 的动画不一致根因（代码实证）：

1. 多口定时器互相打架：每口独立 `scheduleBite(i*680)`，第 i 口的 `closeMouth`（i*680+1360）正好落在第 i+1 口张口中段 → 嘴被合上又弹开。
2. 口数与碗量脱钩：`bites = round(delta/800)` 且 cap 3，5K 和 50K 都可能只嚼 3 口。
3. 碗是连续补间（480ms），嘴是离散口 → 碗在滑、鲸鱼没在嚼。
4. 短回合漏演：1s 轮询可能整段错过 running 窗口，直接结算。
5. 页签隐藏时暂停轮询，回来时碗瞬间变化、没有补演。

v0.5.0 改法：

- **串行咀嚼队列**：同一时刻只有一口，无交叉定时器；张嘴 → 饭团飞 200ms → 咬合（嘴形 + 立绘嚼 + 音效）→ 收尾。
- **每口离散扣饭**：一口吃掉一份，米饭与口数严格同步，不再连续滑落。
- **回合结束补演**：本轮至少 1 口；漏演快速补齐（约 260ms/口，≤4 口）后才出报告气泡；短回合也一定有吃。
- **轮询自适应**：running 450ms / idle 1500ms；`document.hidden` 暂停，恢复时以补演追平。
- 口数计划：`bites = clamp(ceil(consumed / biteVisualTokens), 1, 6)`，参数实测后定。

## 6. 验收标准

- [ ] 任意一轮（含 5 秒短回合）都能看到至少一口吃 + 报告气泡
- [ ] 多口连播无嘴型闪烁/卡住；碗减少与口数一致
- [ ] 5 碗显示与数字一致；> 5 碗 UI 不变
- [ ] 吃完自动讨饭：立绘表演 + 气泡循环且不连续重复

## 8. 风险与边界

- **100 万/碗**：普通一轮 5K 只占 0.5%，肉眼几乎看不出碗变少 → 用数字标签 + 百分比补足；`tokensPerBowl` 做成可配置，后续可调成 10 万/碗。
- 嘴位只适配宿主默认立绘 `DSniang1.png`；换皮肤需改 `config.mouth`（README 写清）。
- README / NOTICE / package.json description 里的旧玩法文案要全部换血（约 18 处）。
- 发布需要 npm 账号与 GitHub 仓库授权，发布前确认。
